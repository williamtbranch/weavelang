# Project Documentation: WeaveLang - V8 Architecture
## The Multi-Tier Simplification & AVD Leveling System

**Document Version: 8.0**
**Last Updated:** (Date of this session)

**Note for LLM (Context for Future Sessions):**
This document is the primary specification for the WeaveLang project. It details a major architectural evolution to a four-tier simplification gradient and a sophisticated, AVD-based leveling system. This supersedes all previous versions.

## 1. Project Overview & Goal

*   **Name:** WeaveLang
*   **Goal:** To create a pedagogically sound language learning system that weans learners from their base language (English) to the target language (Spanish) as efficiently as possible, using a smooth and motivating gradient of comprehensible input.
*   **Core Methodology:** A new **Four-Tier Simplification Gradient** is used to produce text at multiple levels of complexity. A **Tail-Weighted AVD Score** is the canonical metric used to measure difficulty. The final generation engine will use a **Per-Tier Vocabulary Sweep** algorithm to eliminate the "stylistic jarring" of previous models and provide a seamless learning experience.

## 2. The Core Learning Methodology: The Four-Tier Simplification Gradient

Analysis has shown that a single simplification tier creates too large a stylistic gap between ultra-simple text and authentic literary prose. The V8 architecture solves this by pre-processing every advanced sentence into three distinct simplified versions, creating a four-tier ladder of complexity.

*   **L-Adv (Advanced):** The original, unmodified literary text from the source book. This is the final goal for the learner. (`_Baseline` | Tail Score: ~6000+)
*   **L-Mod (Moderate):** A natural and fluent simplification of the advanced text. It uses common synonyms and phrasing but maintains a high degree of stylistic quality. This tier is generated by our `test01` prompt. (Tail Score: ~2000)
*   **L-Bas (Basic):** An intermediate simplification that deconstructs abstract concepts into more concrete phrases, while still aiming for naturalness. It is simpler than Moderate text but less verbose than Simple text. This tier is generated by our `test07` prompt. (Tail Score: ~1000)
*   **L-Sim (Simple):** A radical, NSM-lite simplification that deconstructs concepts into their most basic, high-frequency parts. The phrasing can be unnatural or verbose, but its vocabulary is from the absolute highest frequency band. This tier is generated by our `test04` prompt and serves as the ultimate comprehension on-ramp. (Tail Score: ~600)

## 3. The Universal Difficulty Metric: Tail-Weighted AVD Score

To objectively measure and compare text difficulty, we use a single, robust metric.

*   **Definition:** The **Tail-Weighted Average Vocabulary Density (AVD) Score** is the weighted average of the master frequency list ranks of the words found at the 85th and 95th percentiles of a given text's vocabulary. The formula is: `(P85_Rank + 2 * P95_Rank) / 3`.
*   **Why it Works:**
    1.  **Focuses on the Challenge:** It correctly identifies that text difficulty is determined by the rarest words a learner must know to get through it (the "tail"), not by the thousands of common function words.
    2.  **Robust:** It is insensitive to a few extreme outliers in the 99th percentile, providing a stable measure of the core "challenge vocabulary."
    3.  **Universal Yardstick:** Based on a master frequency list, this score allows us to compare any two texts and state objectively which is lexically more difficult.
*   **Future Refinement (Logarithmic Scale):** To create the final user-facing integer levels (e.g., Level 1-50), this AVD score will be transformed using a logarithmic function. This maps the exponential nature of word frequency to a more linear, perceptually accurate scale of difficulty.

## 4. The Generation Algorithm: Per-Tier Vocabulary Sweep

This is the core innovation of the V8 engine. It solves the "stylistic jarring" problem by ensuring that the engine only ever weaves together text from *adjacent* tiers. This is achieved by tracking vocabulary mastery on a per-tier basis.

1.  **Separate Vocabulary Pools:** The Rust engine will maintain four separate sets of known lemmas, one for each tier: `V-Sim`, `V-Bas`, `V-Mod`, `V-Adv`.
2.  **Sequential Exhaustion:** The generation process for a book starts with all vocabulary pools empty. The engine focuses exclusively on mastering the `L-Sim` vocabulary. The `V-Sim` pool grows until the **exhaustion condition** is met: 100% of the `L-Sim` segments in the book can be rendered in Spanish using only the words in `V-Sim`. During this phase, any segment that fails is rendered using the L1 English Diglot fallback (based on the `L-Sim` tier).
3.  **Tier Promotion and Weaving:** Once `L-Sim` is exhausted, the engine begins filling the `V-Bas` pool. Now, the L0 weave is activated **only between the `L-Bas` and `L-Sim` tiers**.
    *   For each segment, the engine first attempts to use the `L-Bas` version.
    *   If the words are not in `V-Bas`, it falls back to the `L-Sim` version (which is guaranteed to be known).
    *   This ensures the stylistic gap is always minimal (Basic to Simple).
4.  **Continuing the Sweep:** This process continues up the ladder. Once `L-Bas` is exhausted, the weave happens between `L-Mod` and `L-Bas`. Once `L-Mod` is exhausted, the final weave happens between `L-Adv` and `L-Mod`.

This methodology guarantees a smooth progression. The learner is rewarded for mastering a vocabulary tier with audibly more natural and sophisticated prose in their lessons.

## 5. The AVD Calibration Process: Creating Universal Levels

The ultimate goal is to create content where "User Level 20" for *Les Misérables* feels the same as "User Level 20" for a simpler book. The Per-Tier Sweep algorithm and the AVD score enable this.

1.  **Simulation & Measurement:** The pipeline will run a series of simulations on reference texts. It will generate output at various stages of the Per-Tier Sweep (e.g., `V-Sim=500, V-Bas=100`, `V-Sim=700, V-Bas=400`, etc.).
2.  **Data Collection:** For each generated text, it will calculate the final Tail-Weighted AVD Score.
3.  **Create Master AVD Map:** This process creates a master lookup table that maps a target AVD score to the required vocabulary pool sizes (`{V-Sim, V-Bas, V-Mod, V-Adv}`).
4.  **Production Generation:** When the engine is asked to generate a "User Level 20" book, it will:
    a. Look up the target AVD score for Level 20.
    b. Find the corresponding vocabulary pool sizes from the Master AVD Map.
    c. Run the Per-Tier Sweep algorithm with those specific vocabulary limits to produce the final text.

## 6. The Data Pipeline (Python) & Final JSON Structure

*   **Python Role:** The Python pipeline (`PoolManager`) is the data factory. It will be refactored to orchestrate the three separate LLM calls using our validated prompts (`simplify...simple.txt`, `...basic.txt`, `...moderate.txt`) to produce three distinct simplified assets in the common pool.
*   **Lean JSON:** The `FinalizeBook` stage will be updated to produce a lean final JSON. The `Advanced`, `Moderate`, and `Basic` tiers will be stripped of their `tokenized_text`, as the Rust engine only requires their `text` and `lemmas` list. The `Simple` tier will retain its full structure to support the L1 English Diglot fallback.

## 8. Authoring & Studio Features (V8.1 — Friendly Lemmas, Simple Mode, Source Direction)

This section documents the V8.1 layer added on top of the four-tier architecture above to support **author-driven lessons**: short Spanish-authored lesson files that drive the Studio without needing a literary corpus or an AVD calibration step.

### 8.1 Source Direction (`source_is_target`)

`AppState.project_languages` is a `(source, target)` pair. When `source == target` (e.g. both `es`), the Studio is in **Spanish-source mode**: the lesson is already authored in the target language, so the dependency graph reverses for the basic branch.

| Stage                       | English-source (`en` → `es`)             | Spanish-source (`es` → `es`)                            |
|-----------------------------|-------------------------------------------|---------------------------------------------------------|
| `advanced_target` ← `base`  | LLM simplification (`advanced_target_*`) | Verbatim echo (`advanced_segment_es`, segmentation-only) |
| `moderate_target` ← `advanced_target` | LLM simplification              | (unchanged)                                             |
| `basic_target` ← `basic_base`         | LLM translation                  | source flips: `basic_target` ← `base` (`basic_target_simplify_es`) |
| `basic_base` ← `base`       | (unchanged)                              | source flips: `basic_base` ← `basic_target` (`basic_base_translate`, es → en) |

`state.source_is_target()` is **derived**, not persisted — the round-trip flag is `project_languages` itself. Stage dispatch is the single source of truth for `(prompt_name, target_tier, source_tier, segmentation_only)`; see [src/services/tier_graph.rs](../src/services/tier_graph.rs).

> **Known gap (deferred):** Spanish-source `basic_base` is hardcoded to learner language `en`. A future `learner_lang` field on the project will lift that constraint.

### 8.2 Friendly Lemmas + Shielding

`AppState.friendly_lemmas: Vec<String>` is a project-scoped allow-list of target-language lemmas the author wants the learner to encounter literally — never substituted away by the L1 fallback. When `friendly_shielding_enabled = true` (default), the mapping pass applies this rule to the candidate lemma set on each `MappingEntry`:

1. If the friendly list is empty, or no candidate lemma is friendly, the entry is unchanged.
2. Otherwise, **drop every non-friendly lemma**. The friendly subset survives.
3. If multiple friendly lemmas survive, keep the one with the lowest frequency rank (rarer = more pedagogically interesting); ties break by earliest index. Unranked lemmas use `u32::MAX`.

Implementation: `domain::mapping_logic::apply_friendly_shielding`.

### 8.3 Simple Mode

`state.simple_mode = true` collapses the four-tier ladder to its bottom rung — only `basic_base` and `basic_target` are produced, lemmatized, and woven. This is the canonical mode for **author-driven lessons** (Spanish-source) where the author has already produced the simplified target text directly.

Effects:

- **`generate_weave`** — flat `m`/`a` modes are rejected; numeric levels with `mod_v>0` or `adv>0` are dropped (errors on single-level requests, silently skipped with an inline note in `all`).
- **`run_drc`** — rules 1–3 skip `advanced_target` and `moderate_target` tiers entirely; rule 6 (adv/mod segment-count match) is skipped.
- **`AvManifest::validate_for_simple_mode`** — flags any `ULm` / `ULa` marked stems.
- **Title bar** — appends ` [simple mode]`.

### 8.4 Teaching Mode (Preset)

A convenience preset, not a persisted flag. `set teaching_mode on` applies:

```
simple_mode = on
frontier_enabled = off
friendly_shielding_enabled = on   (force-enabled with warning if it was off)
```

`set teaching_mode off` is a deliberate **no-op** — it does not unset the underlying flags. The Project Flags pane shows `teaching_mode: on` only when all three derived conditions hold (otherwise `custom/off`).

### 8.5 Lesson Directive Syntax

Lesson source files (the `.txt` consumed by `import source`) may begin with a `%%META%%` preamble. All directives are case-insensitive on the key. See [src/parsing/source_parser.rs](../src/parsing/source_parser.rs).

```
%%META source_language: es%%
%%META target_language: es%%
%%META book_name: Caballero%%
%%META simple_mode: on%%
%%META frontier_enabled: off%%
%%META friendly_shielding: on%%
%%META friendly_lemma: de%%
%%META friendly_lemma: con%%
%%META teaching_mode: on%%             # preset; expands to simple_mode=on + frontier=off
%%META lm_entry: bas=10%%              # absolute embedded level-map entry, anchored to next sentence
%%META lm_entry: bas=+1%%              # relative bump from previous entry
%%META lm_entry: bas=15, from=S42%%    # explicit anchor sentence
%%META lesson_progression: bas_start=1, step=1, per=lesson%%
%%META lesson_marker%%                 # demarcates the start of a lesson within the body
```

`lm_entry` and `lesson_progression` require `simple_mode=on` (rejected with a warning otherwise) — embedded level maps assume the basic-only weave. They set `state.level_map_embedded = true`, which Phase H will use to reject `calibrate` and gate the future `strip_level_map` command.

### 8.6 Project Flags Pane

The Studio exposes all V8.1 flags via two equivalent surfaces:

- **Terminal:** `flags` (read-only print) and `set …` / `set_friendly_lemma` / `unset_friendly_lemma` / `clear_friendly_lemmas` write commands.
- **GUI:** Preferences → **Project Flags…** modal. Every checkbox / button issues the matching terminal command via `execute_terminal_command`, so behavior is identical across surfaces.

The pane displays:

| Field                  | Source                                   |
|------------------------|------------------------------------------|
| `source_language`      | `state.project_languages.0`              |
| `target_language`      | `state.project_languages.1`              |
| `source_is_target`     | derived: `project_languages.0 == .1`     |
| `book_name`            | `state.book_name`                        |
| `simple_mode`          | `state.simple_mode` (toggle)             |
| `frontier_enabled`     | `state.frontier_enabled` (read-only when teaching_mode active) |
| `friendly_shielding`   | `state.friendly_shielding_enabled` (toggle) |
| `teaching_mode`        | derived (button to apply preset)         |
| `friendly_lemmas`      | `state.friendly_lemmas` (add / remove / clear) |
| `level_map`            | embedded / calibrated-imported / none    |

### 8.7 Authoring a Lesson File — Quick Guide

1. Pick a source-direction. For Spanish-authored lessons, set both languages to `es`.
2. Write a short META preamble (see §8.5). The minimal Spanish-source teaching-mode preamble is:

   ```
   %%META source_language: es%%
   %%META target_language: es%%
   %%META teaching_mode: on%%
   %%META lesson_progression: bas_start=1, step=1, per=lesson%%
   %%META friendly_lemma: de%%
   ```

3. Author the lesson body as plain Spanish text. Use `%%META lesson_marker%%` on a line by itself to mark each new lesson boundary; the embedded level map will bump `bas` per the `lesson_progression` recipe at each marker.
4. `import source <path>` in the Studio. The flags pane should now show `simple_mode: on`, `frontier_enabled: off`, `friendly_shielding: on`, `source_is_target: yes`, and `level_map: embedded`.
5. Approve the basic tiers as usual. `generate_weave all` will produce only the basic-tier outputs; `generate_weave m` / `a` are rejected.

### 8.8 Backward Compatibility

- A lesson file with **no** META directives parses to a `SourceMeta` with all fields `None`/empty — the import flow leaves `state` defaults intact. English-source projects without directives behave exactly as in V7.
- Persistence: `simple_mode`, `friendly_shielding_enabled`, `frontier_enabled`, `friendly_lemmas`, `level_map_embedded`, and `book_name` round-trip through `.wvl`. `source_is_target` is derived and never serialized.
