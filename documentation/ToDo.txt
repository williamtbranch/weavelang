### Primary Objectives & Guiding Principles

- **Goal:** To dramatically increase the quality and stylistic consistency of the L1 learning tiers by integrating a mandatory human review and editing process into the pipeline.
- **Architecture:** The Python pipeline will be refactored into a state machine with explicit "pause" points. It will generate human-readable files with a commented-out "approval marker." The pipeline will only proceed once the user has edited the file and uncommented the marker.
- **Golden Rule:** The human-edited "golden pair" of `basic_english` and `basic_spanish` will be the sole source of truth for all L1 content, ensuring maximum quality and consistency.

### Master Checklist
---

#### Phase 1: Stateful Orchestrator and New Pipeline Stages (Python)

- [ ] **Task 1.1: Refactor the Main Orchestrator (`orchestrate_pipeline.py`)**
    - [ ] **Implement State Machine Logic:** The orchestrator must check for files in a dedicated `human_review` directory and parse their first line to determine the pipeline's state.
    - [ ] **State 1 (Start):** No `*.basic_en.txt` exists -> Run `GenerateBasicEnglish`.
    - [ ] **State 2 (Awaiting English Review):** `*.basic_en.txt` exists, but `%%HUMAN_REVIEW_APPROVED%%` is commented out or missing -> Halt with instructions.
    - [ ] **State 3 (Awaiting Mapping Review):** `*.basic_en.txt` is approved, but `*.dig.txt` or `*.invdig.txt` are not approved -> Run translation and mapping stages.
    - [ ] **State 4 (Awaiting Finalization):** All review files are approved -> Run the final consumption and finalization stages.

- [ ] **Task 1.2: Create New Stage - `GenerateBasicEnglish` (Stage 2)**
    - [ ] This stage takes the original `base` tier as input.
    - [ ] It uses a new `simplify_to_basic_english.txt` prompt to generate simplified English.
    - [ ] **Output:** It will create a single text file (e.g., `Metamorphosis.basic_en.txt`) in the `human_review` directory.
    - [ ] **Crucially, the first line of this file MUST be `# %%HUMAN_REVIEW_APPROVED%%`.**

- [ ] **Task 1.3: Create New Stage - `TranslateBasicSpanish` (Stage 3)**
    - [ ] On resume, this stage's input logic must first validate that `Metamorphosis.basic_en.txt` exists and its approval marker is uncommented.
    - [ ] It will then read this human-approved file as its source of truth, translate it to create the `basic_spanish` tier, and populate the main JSON object.

- [ ] **Task 1.4: Refactor Mapping Stages to Generate Review Files**
    - [ ] Modify `GeneratePhraseMap` (now Stage 4) to generate `book.dig.txt`. The first line must be `# %%HUMAN_REVIEW_APPROVED%%`.
    - [ ] Modify `GenerateInverseDiglotMap` (now Stage 5) to generate `book.invdig.txt`. The first line must be `# %%HUMAN_REVIEW_APPROVED%%`.
    - [ ] Both stages must still run their internal validation logic *before* writing the review files to ensure the template you edit is valid.

#### Phase 2: Validation and Override Consumption (Python)

- [ ] **Task 2.1: Implement Pre-Consumption Validator for Approved Files**
    - [ ] Create a dedicated validation step at the start of the final pipeline phase.
    - [ ] This step will read `*.dig.txt` and `*.invdig.txt` only after confirming their approval markers are uncommented.
    - [ ] It will perform a full structural validation on the *entire file content* (e.g., by running `refactor_token_stream` on every sentence's mappings).
    - [ ] If any error is found, the pipeline must HALT with clear, actionable error messages.

- [ ] **Task 2.2: Refactor `Apply...Mappings` Stages to Consume Approved Files**
    - [ ] Modify `ApplyPhraseMappings` (now Stage 6) to read the validated and approved `book.dig.txt` file as the *sole source of truth* for building the final JSON mapping structures.
    - [ ] Modify `ApplyInversePhraseMappings` (now Stage 7) to do the same with the `book.invdig.txt` file.

#### Phase 3: Rust Engine Refactor

- [ ] **Task 3.1: Update JSON Parsing and Numerical Types (`json_types.rs`, `preprocessor.rs`)**
    - [ ] Remove the `simple_target` tier from the structs.
    - [ ] Add the new `basic_english` tier.
    - [ ] The L0 `NumericalAdvSegmentBundle` will now only contain `adv` and `mod` tiers.
    - [ ] The `NumericalProcessedSentence` struct must be updated to reference the `basic_english` and `basic_target` tiers for L1 fallback logic.

- [ ] **Task 3.2: Implement the New L0/L1 Weaving Logic (`core_algo.rs`)**
    - [ ] Modify `try_build_advanced_weave`. The fallback cascade is now only: `Advanced -> Moderate`. If both fail, the L0 weave fails.
    - [ ] Modify `determine_and_annotate_sentence_expression`. If `try_build_advanced_weave` returns `None`, implement the new L1 logic:
        1. Check if the learner's profile knows >= 50% of the lemmas in the `basic_target` sentence.
        2. If yes, construct the output from the full `basic_target` text.
        3. If no, construct the output using the `basic_base` (i.e., `basic_english`) text and its corresponding diglot map.

- [ ] **Task 3.3: Update the WeaveLang Test Suite (`.weavetest`)**
    - [ ] Modify the `.pest` grammar to remove the `Simple` and `Basic` tiers from the L0 definition. The L1 definition will now be based on the new `Basic` pair.
    - [ ] Create new test cases that specifically assert the correct fallback behavior: a test for `Mod -> L1` failure, a test for the L1 50% check *passing*, and a test for the 50% check *failing*.

#### Phase 4: Finalization and Cleanup

- [ ] **Task 4.1: Update `FinalizeBook` Stage (Stage 9)**
    - [ ] The logic for stripping `tokenized_text` is still valid, but the list of tiers to strip is now just `advanced_target` and `moderate_target`. `basic_target` and `basic_english` must be preserved.
    - [ ] Update the final schema version number.

- [ ] **Task 4.2: Update Project Documentation**
    - [ ] Update all relevant documentation to reflect the new two-tier L0 weave, the human-in-the-loop "approval marker" process, and the new 50% check in the L1 fallback logic.

- [ ] **Task 5.1 (V12 Optimization): Implement LLM Caching**
    - [ ] Refactor `llm_utils.py` to support prompt caching for both Anthropic and Gemini providers.
    - [ ] Update `LLMStage` to manage the lifecycle of a cached system prompt for the duration of its run.
    - [ ] Measure cost savings on a full book run.
